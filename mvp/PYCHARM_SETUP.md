# Запуск в PyCharm

Откройте корень скачанного репозитория как проект.

## Интерпретатор

Приложение использует только стандартную библиотеку Python. Можно выбрать установленный системный Python 3.14 или создать локальное окружение из терминала в корне репозитория:

```powershell
py -3.14 -m venv .venv
```

После этого выберите интерпретатор `.venv/Scripts/python.exe`. Папка `.venv` в репозиторий намеренно не включена.

## Настройки запуска app.py

- Файл скрипта: `mvp/app.py`.
- Рабочая папка: `mvp`.
- Параметры: `--db mvp.sqlite`.
- Интерпретатор: системный Python 3.14 или `.venv/Scripts/python.exe`.

Запустите приложение и откройте `http://127.0.0.1:8000`. Если порт занят, добавьте `--port 8001` и откройте соответствующий адрес.

## Зависимости

Приложение использует только стандартную библиотеку Python. Устанавливать `sqlite3`, `http` или другие встроенные модули через `pip` не нужно. `requirements.txt` фиксирует отсутствие сторонних зависимостей.

Для необязательной проверки стиля:

```powershell
.\.venv\Scripts\python.exe -m pip install -r mvp/requirements-dev.txt
```

## Проверки

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe mvp/selftest.py
.\.venv\Scripts\python.exe mvp/regression_test.py
.\.venv\Scripts\python.exe mvp/integration_test.py
```

Или без виртуального окружения:

```powershell
py -3.14 mvp/selftest.py
py -3.14 mvp/regression_test.py
py -3.14 mvp/integration_test.py
```

Готовая демонстрационная база включена в проект. `seed.py` нужен только для восстановления исходного состояния; при локальном повторном запуске он может создать резервную копию `mvp.sqlite.bak`.
