# Поступашки: конкурсное решение

Этот репозиторий собирает итоговое решение кейса: от разведочного анализа продаж до работающего прототипа измерительной системы.

## Главная идея

Прошлую рекламу можно частично восстановить, но нельзя честно связать каждый рубль выручки с конкретным размещением. Поэтому решение сочетает фактический анализ прошлого с системой измерения будущих запусков.

## Что сделано

1. Разведочный анализ продаж: 795 строк, 628 заказов, 606 покупателей, 5 904 672 рубля выручки.
2. Восстановлена публичная маркетинговая история и сопоставлена с пиками продаж.
3. Спроектирована целевая система измерения: реестр рекламы, ссылки, касания, лиды, заказы, оплаты и витрины.
4. Выбрана многокасательная атрибуция с окном семь дней.
5. Разделены атрибуционная окупаемость и причинная окупаемость.
6. Построен недельный прогноз продаж с обратной проверкой.
7. Собран рабочий прототип, который проводит пользователя от рекламного размещения до оплаты и пересчёта окупаемости.

## Как запустить прототип

Перейти в папку mvp и выполнить команды:

```bash
python seed.py
python selftest.py
python integration_test.py
python regression_test.py
python app.py
```

После запуска открыть локальный адрес, показанный в консоли.

## Основные папки

- data — исходные и подготовленные данные.
- reports — рабочие книги по этапам анализа.
- mvp — рабочий прототип измерительной системы.
- charts — изображения для презентации.
- docs — условие кейса и финальные материалы для защиты.

## Финальные материалы

В папке `docs` лежат:

- `case.pdf` — условие кейса;
- `final_presentation.pdf` — финальная презентация для защиты;
- `final_presentation.pptx` — редактируемая версия презентации;
- `executive_summary.pdf` — финальный краткий отчёт на две страницы;
- `executive_summary.pptx` — редактируемая версия краткого отчёта.

## Что показывать на защите

Лучший сценарий: создать рекламное размещение, открыть созданную ссылку, выполнить склейку пользователя, оформить оплату и показать, что атрибуция и окупаемость пересчитались автоматически.

## Ограничения

Прошлые продажи не имеют пользовательских рекламных касаний, стоимости всех размещений и контрольной группы. Поэтому историческая причинная окупаемость по каналам не заявляется. Все синтетические данные используются только для проверки будущего контура измерения.

В Windows при недоступной команде `python` используйте `py -3.14`. Сборка `seed.py` использует CSV из `mvp/data`, проверяет временную базу и заменяет рабочую только после успешной сборки. Локальная резервная копия `mvp.sqlite.bak` создаётся при повторной сборке, но в репозиторий не включается.

## Стиль Python-кода

Имена переменных, функций и классов написаны на английском.
Русские строки интерфейса и поля SQLite/CSV сохранены.
Правила форматирования и линтинга заданы в `mvp/pyproject.toml`. Инструменты проверки перечислены в `mvp/requirements-dev.txt` и не требуются для запуска приложения.

Проверка из папки mvp:

```powershell
py -3.14 -m pip install -r requirements-dev.txt
py -3.14 -m ruff check .
py -3.14 -m ruff format --check .
py -3.14 -m pycodestyle --max-line-length=79 .
```
